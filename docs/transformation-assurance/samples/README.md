# Sample reports

These synthetic display reports were generated by
`python scripts/generate_fixture_reports.py` from the public fixtures through
the real workflow. They contain no customer data. Machine-specific paths were
replaced for publication, so these Markdown copies are examples rather than
unchanged raw evidence. Regenerate them after any change to the report layout.

| file | what it is |
|---|---|
| `repair-shop.md` | a governed repair of `fixtures/ugly_shop`: unit u1 (the valid refactor) verified and accepted, unit u2 (the cleaner but wrong refactor) caught by the counterexample search with a minimized ten-unit order, rejected and rolled back; final verdict `PASS` on the accepted state |
| `finite-shipping-proved.md` | `fixtures/finite/target_ok.py` proved equivalent to `source.py` over all eighty members of the declared domain |
| `finite-shipping-diverged.md` | `fixtures/finite/target_bad.py`: two of eighty members diverge; the minimal one is the counterexample; verdict `BLOCK` |

The Markdown files lead with the six plain-language sections and are the
non-coder report. The complete JSON machine records are intentionally not
published with these display examples. The sandbox and fixture directories
were replaced by `<sandbox>` and `<fixture-root>`, so the displayed provenance
does not validate against the original session digest. A report you generate
yourself retains its unchanged machine record and digest.
